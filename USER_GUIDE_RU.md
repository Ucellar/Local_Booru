# Local Booru v130 — короткая инструкция

## Главное правило безопасности

**Основной архив является источником только для чтения.** Local Booru копирует нужные файлы в рабочую библиотеку и меняет только её:

- исходные файлы: не удаляются, не перемещаются и не перезаписываются;
- рабочая галерея, SQLite, кэш и корзина: можно сбрасывать и пересобирать для тестов.

На нижней строке окна всегда должно быть видно: **«Исходный архив: только чтение»**.

## Первый запуск тестовой сборки

1. В **Настройки** укажи папку исходного архива и папку рабочей выдачи.
2. Открой **Обзор** и нажми **Обновить состояние**.
3. В **Диагностика** нажми **Проверить библиотеку**.
4. Убедись, что значение **Групп MD5-дублей** не растёт после нового прогона парсера.
5. Только после проверки запускай длинный поиск.


## Переход со старых результатов

В обычной работе метаданные хранятся только в SQLite. Старые `.tags/.sources` файлы не считываются скрытно при каждом открытии галереи. Для старой выдачи используй отдельное действие **Настройки → Обслуживание → Импортировать старые sidecar в SQLite**; перед импортом создаётся backup базы.

Старые JSON-состояния брака и удалённых MD5 импортируются один раз автоматически с резервными копиями. Файлы `.nomatch` больше не создаются и не используются как состояние поиска.

## Если SauceNAO ушёл в кулдаун

Парсер не останавливается:

- обычные сайты продолжают MD5-поиск;
- при обычном новом поиске IQDB и включённый Ascii2D проверяются до SauceNAO, чтобы не расходовать его лимит там, где найден бесплатный результат;
- оставшиеся файлы записываются в долговечную очередь SauceNAO;
- после перезапуска очередь восстанавливается без повторного расхода IQDB;
- живой повтор после кулдауна отображается в **Диагностика → Очереди**.

## Диагностика и ремонт

**Диагностика** только читает базу. Она показывает дубли, пропуски source/тегов, очереди, ошибки, корзину и защиту оригиналов.

Ремонт выполняется только отдельными кнопками:

- **Создать backup базы**;
- **Склеить точные MD5-дубли**;
- **Снять запреты для живых MD5**;
- **Восстановить индексы SQLite**.

Перед ремонтом останови парсер. Корзину не очищай, пока не проверишь несколько объединённых карточек и их источники.

## Проверка скорости

В **Диагностика** нажми **Замерить скорость SQLite**. Вкладка **Замер SQLite** покажет, что именно тормозит: теги, source, страницу галереи или проверку дублей.

Медленные действия также пишутся в `logs/performance.jsonl`.

## Настройки и перенос

В **Настройки** доступны:

- **Экспорт профиля настроек** — сохраняет интерфейс, сайты и параметры работы;
- **Импорт профиля настроек** — применяет профиль с backup текущих настроек.

По умолчанию экспорт не включает логины и API-ключи. SQLite и медиафайлы в профиль не входят никогда.

## Что присылать при баге

Для разбора достаточно:

1. скриншот странного поведения;
2. кусок лога вокруг ошибки;
3. JSON из **Диагностика → Экспорт отчёта**;
4. при падении — ZIP через **Настройки → Собрать отчёт об ошибке**.

## Безопасность API-ключей и логов (v121)

С версии v121 журналы и отчёты автоматически маскируют API-ключи, логины, токены и значения cookies. При первом запуске старые файлы в папке `logs` обезличиваются на месте.

Если старый лог уже был кому-либо отправлен до v121, перевыпусти соответствующие API-ключи на сайтах. В **Диагностика** есть кнопка **«Обезличить старые логи»** для повторной ручной проверки локальной папки журналов.


## SQLite и тестовая библиотека в v130

- Исходный архив защищён: программа может только читать и копировать исходники.
- `Local_Booru_Archive/output` и рабочая SQLite — производные данные; на этапе разработки их можно пересобрать.
- При запуске SQLite проверяется до любых записей. Если проверка не пройдена, приложение входит в режим только чтения и предлагает открыть диагностику/пересобрать рабочую библиотеку.
- В `Настройки → Обслуживание` доступны backup, статистика, `PRAGMA optimize` и явное сжатие `VACUUM`. `VACUUM` запускай только после остановки Парсера.


## Изменение v133 — экономия лимита SauceNAO

- Поддерживается один API-ключ SauceNAO; ротация ключей не добавляется.
- Обычная цепочка запасного поиска: MD5-сайты → IQDB → Ascii2D (если включён) → SauceNAO.
- Повтор из очереди после кулдауна выполняет только SauceNAO: IQDB и Ascii2D второй раз не запускаются.
- Остаток короткого и суточного лимита SauceNAO сохраняется в SQLite и показывается в настройках парсера/диагностике после первого ответа API.
- Строки сетевого журнала получили префиксы файла и полосы (`[MD5:...]`, `[REVERSE:...]`, `[SAUCENAO-RETRY:...]`), чтобы параллельный вывод не смешивал разные изображения визуально.

## Изменение v134 — объединение результатов IQDB по сайтам

- Если IQDB нашёл несколько похожих постов на одном сайте, парсер применяет теги только одного лучшего поста этого сайта.
- Если IQDB нашёл подходящие посты на разных включённых сайтах, парсер берёт по одному лучшему результату с каждого сайта и объединяет их теги и ссылки-источники.
- Точный MD5, явно присутствующий в ссылке IQDB и совпадающий с файлом, имеет приоритет над визуально похожим вариантом того же сайта.
- Это позволяет использовать дополняющие теги Danbooru/Gelbooru/других источников, не смешивая несколько близких изображений внутри одного booru.


## Структура общего архива

При включённом хранении данных в общем архиве программа использует только следующий рабочий корень:

```text
Local_Booru_Archive/
├── output/                         # медиа и содержимое архива
└── settings/                       # служебные данные программы
    ├── config/                     # app_settings.json
    ├── db/                         # SQLite
    ├── cache/                      # превью и кэш поиска
    └── output/                     # журналы, cookies/runtime и резервные копии
```

Настройки, SQLite, кэш, API-ключи и cookies хранятся только внутри `Local_Booru_Archive/settings`. Чтобы новая распакованная версия сразу находила уже подключённый архив, приложение хранит два маленьких указателя с одним путём: `local_booru_workspace.json` рядом с программой и `%LOCALAPPDATA%/Local_Booru/workspace_pointer.json`. Они не содержат API-ключи, логины или cookies. При активном общем архиве полная копия настроек в `Documents/Local_Booru` больше не создаётся. Если указатель от старой версии был потерян, в настройках нажми `Подключить существующий архив...` и выбери `Local_Booru_Archive`.

## Если после подключения архива снова показываются старые пути
Начиная с v137 подключённый `Local_Booru_Archive` является главным источником путей. Даже если в перенесённом `settings/config/app_settings.json` остались старые значения `Local_Booru_Output` или `Documents/Local_Booru`, при запуске они автоматически исправляются на:

```text
Local_Booru_Archive/output
Local_Booru_Archive/settings
```

После подключения существующего архива перезапустите программу один раз. В активном переносимом архиве переключатель хранения служебных данных заблокирован включённым; для смены архива используйте кнопку **«Подключить существующий архив...»**.

## Брак после переноса архива в новую папку

Если старые результаты `NO_MATCH` были созданы до перехода на `Local_Booru_Archive`, их служебная копия могла находиться в удалённой папке `Local_Booru_Output`. Начиная с v138 вкладка **Брак** использует исходный файл для предпросмотра, если старая копия отсутствует, и отмечает его как **[восстановить копию]**.

Нажатие **Повторить поиск** перед новым поиском пересоздаёт нужные копии в текущей папке:

```text
Local_Booru_Archive/output/no_match/media/
```

Исходный файл при этом не перемещается и не удаляется.

## Теги по источникам и защита от мусора HTML (v139)

Начиная с v139 теги файла не смешиваются безвозвратно в один набор. Для каждого
сайта хранится собственный набор метаданных, например:

```text
файл.png
├── rule34.xxx       → его теги
├── gelbooru.com     → его теги
└── danbooru.donmai.us → его теги
```

В режиме **Все источники** показывается объединение без повторов: одинаковый
`vaporeon` от нескольких сайтов виден один раз. При выборе конкретного сайта
в галерее, карточке поста или разделе тегов показываются только его теги.

Для `rule34.xxx` точный DAPI/API-ответ определяет допустимый список тегов.
HTML-страница может лишь указать категорию уже подтверждённого тега; новый тег
из HTML никогда не добавляется в файл. `artist_request` показывается как
служебный/meta-тег, а не как имя художника. `rule34.us` остаётся HTML-only
источником после строгой проверки MD5.

Старые результаты, созданные до v139, могут уже содержать смешанные или
ошибочные теги, происхождение которых в старой базе не записывалось. Для
полностью чистой библиотеки удалите рабочие результаты/SQLite и прогоните
поиск заново; исходная папка с вашими файлами при этом не удаляется.

## Если удаление сообщает, что GIF занят другим процессом (v139)

Раньше просмотр открытого GIF мог удерживаться компонентом Qt `QMovie`, и
Windows запрещала очистить `output/found` с ошибкой `WinError 32`. В v139 перед
удалением программа отсоединяет предпросмотр/видеоплеер и несколько раз
повторяет временно заблокированную операцию. Перед полной очисткой всё равно
остановите Парсер и закройте пост, если файл открыт внешней программой.

## Категории тегов Gelbooru
Если Gelbooru отдаёт точный пост через DAPI, но список тегов в API не разделён по категориям, Local Booru в фоне открывает страницу этого же поста и использует её только для распределения подтверждённых DAPI-тегов по группам. Новые теги из HTML-страницы автоматически не добавляются. После обновления со сборки v139 существующие записи Gelbooru могут постепенно переразложиться в фоне без повторного поиска файла.


## Источник тегов при просмотре постов (v141)
Выбранный источник тегов в карточке поста сохраняется при переходе стрелками между файлами. Если выбран, например, `gelbooru.com`, а у следующей картинки тегов этого сайта нет, Local Booru сохраняет выбор и показывает пустой список с пояснением; чтобы снова видеть объединение, выберите «Все источники».

### Категории тегов Gelbooru

Для `gelbooru.com` Local Booru получает список тегов точного найденного поста через API постов, а их категории — через API списка тегов Gelbooru. Поэтому в выбранном источнике Gelbooru теги должны разделяться на художника, персонажа, произведение, служебные и общие теги. Если API категорий временно недоступен, фоновая безопасная переразметка может повторить классификацию; она не добавляет тегов, которых не было в точном посте.

### Длинные теги в боковой панели
В просмотре поста боковая панель тегов сохраняет постоянную ширину. Если имя тега слишком длинное, оно показывается сокращённо с `…`; наведите курсор на тег, чтобы увидеть полное имя. Поиск и действия выполняются с полным тегом, а не с сокращённой подписью.

### Уточнение категорий одинаковых тегов между источниками (v144)
Если несколько сайтов подтвердили один и тот же тег у одного файла, Local Booru может повысить его категорию из `general` в более информативную группу, известную другому источнику. Например, если Gelbooru оставил `alan_smithee` общим тегом, а Danbooru определил этот же тег как художника, в просмотре Gelbooru он также будет показан в группе `artist`.

Категории работают только в сторону уточнения: `general` может перейти в `artist`, `character`, `copyright`, `meta` или другую специальную группу, но уже классифицированный тег никогда не опускается обратно в `general`. При этом новые теги от другого сайта не добавляются: уточняется только категория тега, который уже был получен выбранным источником.

### Защита источников от страниц поиска и галереи (v145)
Кнопка в разделе «Источники» должна открывать конкретный пост сайта, а не главную страницу или результаты поиска. Local Booru не сохраняет Gelbooru-ссылки вида `page=post&s=list&tags=all` и другие навигационные/random-страницы как источник изображения. При обновлении со старой версии такие ошибочные ссылки автоматически удаляются из рабочей базы; реальные ссылки других сайтов остаются на месте.


### Неподтверждённые ссылки обратного поиска
Ссылка из IQDB не считается источником файла, пока соответствующий сайт не отдал метаданные поста. Если Gelbooru перенаправляет кандидат на галерею или API не возвращает пост/теги, такая кнопка не сохраняется в списке источников.

## v147: предпросмотр Брака и передача источника из Галереи

- Во вкладке «Брак» GIF теперь показываются через встроенный QMovie-предпросмотр.
- Видео в «Браке» показываются статичным кадром через общий кэш превью. Полное воспроизведение остаётся через кнопку «Открыть файл» или через просмотр поста.
- Если в Галерее выбран конкретный источник тегов, например `danbooru.donmai.us`, при открытии поста слева сразу показываются теги этого же источника. Для режима «Все источники» открывается объединённый режим.

## v148: лёгкие резервные копии

В настройках в блоке «Перенос и экспорт данных» можно включить лёгкие резервные копии. Они сохраняют только SQLite-базу, настройки и manifest.json. Медиафайлы, превью и кэш не копируются.

Рекомендуемая папка назначения — внешний SSD или другой диск. Можно включить создание копии при закрытии приложения и периодический интервал для долгих сессий. Если диск недоступен, приложение не должно блокировать закрытие; следующая копия будет создана при следующей доступной попытке.


## v149: визуальная чистка интерфейса

В современных темах интерфейс стал менее плотным: выровнены высоты кнопок и полей, улучшены вкладки, списки, таблицы, строка состояния и визуальное разделение опасных действий. Это не меняет данные и парсер — правка только про читаемость и внешний вид.

Опасные действия вроде удаления выделяются отдельно. Основные действия вроде сохранения, обновления, создания резервной копии и повторного поиска подсвечиваются сильнее. Вторичные кнопки остаются спокойными.


## v151

Исправлена визуальная полировка тем: общий слой UI больше не навязывает сине-фиолетовый акцент темам Ember/R34/PH/Sakura. Выделение строк, primary-кнопки и рамки выбранных превью используют акцент текущей темы.

## v152: фон тем и мягкая шахматка таблиц

В темах Ember и Sakura поправлен фон: Ember больше не должен выглядеть сине-фиолетовым, а Sakura стала темнее и менее кислотной. Чередование строк теперь используется только в таблицах и намного слабее, с оттенком текущей темы. Списки тегов, источников и «Брака» остаются без шахматки, чтобы цвет категории и выделение строки не смешивались с лишними полосами.

## v153 — темы и таблицы
- Ember/Sakura: убраны старые холодные/фиолетовые фоновые цвета из страницы настроек и общей палитры.
- Табличная шахматка должна быть слабой и в цвет темы; системный синий AlternateBase больше не должен протекать в таблицы.
- R34/R34 Dark остаются compact old-web темами, без раздувания навигации современным слоем.


### v154: подсветка кнопок управления

Кнопки управления теперь читаются по доступности: яркая кнопка означает, что действие можно нажать сейчас. Во время работы парсера «Старт» приглушается, а «Пауза» и «Стоп» остаются заметными. После завершения или остановки «Старт» снова становится основной доступной кнопкой.

### v155: видимые галочки
В темах интерфейса исправлено отображение чекбоксов: включённые параметры теперь показывают явную галочку, а не только изменение цвета квадрата. Это касается обычных настроек и чекбоксов внутри таблиц.

## v157 — отсутствующие файлы и source-only Брак

- Если запись в SQLite указывает на файл, которого уже нет на диске, галерея и просмотр поста показывают явное состояние «Файл отсутствует», а не обычную загрузочную заглушку.
- SauceNAO-совпадения по неподдерживаемым источникам сохраняются как `source_only`: источник найден, но теги Local Booru получить не может.
- Вкладка «Брак» разделяет обычный `NO_MATCH`, `source_only` и записи с отсутствующим файлом.
- `no_match_items` расширена полями `source_url`, `source_label`, `source_host`, `source_similarity`, `last_error`; схема SQLite v20.


## v271: диагностика reverse-кандидатов и Pixiv/source relay

В режиме парсера SauceNAO теперь сохраняет диагностические reverse-кандидаты в файл:

`Local_Booru_Archive/settings/output/logs/reverse_candidates.log`

Файл нужен для проверки случаев, когда SauceNAO нашёл неподдерживаемый сайт вроде Pixiv, Fanbox/Kemono, FurAffinity, E-Hentai, DeviantArt и т.п. Такие сайты не считаются источником тегов напрямую. ## Blueprint парсера: full-access режим

В v321 парсер по умолчанию работает через стандартный Blueprint-граф. Этот граф повторяет обычный текущий парсер, поэтому без ручных изменений поведение должно оставаться привычным.

В разделе `Blueprint` можно редактировать блоки: двойной клик по блоку открывает расширенный редактор. У каждого блока можно менять потоки, задержку, таймаут, повторы, группу лимита, входы/выходы и JSON-настройки. Входы показываются слева, выходы справа.

Режим `Можно всё / ответственность пользователя` не запрещает опасные схемы, а показывает предупреждения. Запуск блокируется только если граф физически невозможно маршрутизировать: отсутствует блок, отсутствует порт, повторяется ID.

Если добавить сайт в настройках сайтов, для него автоматически появляется блок `MD5: <domain>` в палитре Blueprint. При включённом автодобавлении сайт добавляется в стандартную MD5-ветку. Если сайт выключен в настройках, его блок остаётся на графе, но runtime пропускает его как skip/pass-through.

Важно: v321 ещё использует существующий parser conveyor как исполнительный слой. Blueprint уже управляет порядком сайтов, включением reverse-веток, worker/delay настройками MD5-сайтов и количеством fallback workers, но полный per-node executor/job ledger — следующий этап.

### v343: Yande.re/Pixiv как доноры MD5

В обратном поиске ссылки Yande.re и Pixiv используются только как источник MD5/оригинала. Теги с Yande.re/Pixiv не импортируются как основные теги.

- Yande.re: из `post/show/<id>` берётся `md5` через JSON API, затем этот MD5 проверяется на включённых основных сайтах.
- Pixiv: из `artworks/<id>` берётся URL оригинала, оригинальный файл скачивается для подсчёта MD5, затем этот MD5 проверяется на включённых основных сайтах.
- Для Pixiv с несколькими страницами проверяются несколько original-файлов.

### Pixiv/Yande.re как доноры MD5
Yande.re используется только для получения `md5` поста через JSON и последующей проверки этого MD5 на основных источниках. Теги Yande.re не используются.
Pixiv используется только как источник original URL: расширение Local Booru Companion может получить JSON Pixiv из уже открытой вкладки Chrome, приложение скачивает original-файл и считает MD5, затем проверяет этот MD5 на основных сайтах. Local Booru не запускает новый Chrome для Pixiv.
